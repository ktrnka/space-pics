# Space pics build day: retrospective (Claude's draft)

**Date**: 2026-09-17
**Repo**: ktrnka/space-pics, main
**Written before reading Keith's retro, for calibration.**

## Summary

Goal: in one time-boxed day, ship a site that shows a recent space image daily from several sources, with RSS and an
unattended job. Shipped by 10:33; the rest of the day went to what the must-do didn't ask for and turned out to
matter more: an explorer over all the data, a subject-of-the-day digest with instrument cards, eleven sources, and a
first "interesting" signal. 68 commits, freeze on time, tomorrow's run is the first unattended one.

## What went well

- **Offline-first parallelism.** Fetching feeds and images once, then handing subagents only saved data with a
  no-network rule and disjoint file sets, produced seven extractors, 47 instrument cards, and three reviews with
  zero collisions and no load on the sources. The pattern is worth keeping as the default for this repo.
- **Keith's viewing time was the highest-value input of the day.** The explorer review at 13:05 reframed the plan;
  the anomaly page produced the "picture types" insight; the wigglegram verdicts were better than my metrics.
  Every hour spent building a surface for him to look at paid back within the hour.
- **Cheap experiments answered big questions.** Twenty minutes of DINOv2 plus a frame-difference script settled the
  ranker design for two subjects before any ranker code existed.

## What didn't go well

- **Deploys were broken for four hours and every status check said success.** Push-triggered runs built the site
  and silently skipped the deploy job. I checked run conclusions six times and the served page never. Keith found
  it by looking. Root cause: I treated "the job passed" as "the thing is live".
- **I reached the pick-1 demo too early and stayed there too long.** The handoff's build order put a working
  pipeline first, and I followed it past the point where it was useful. Keith's noon observation, "we jumped from
  the debug page to the pick-1 demo too early", was the day's most important correction, and it came from him,
  not from me noticing that the explorer was where all the learning happened.
- **My predictions lost to his eyes three times.** Calibration frames at the centroid (wrong: they're outliers on
  Mastcam-Z); gzip the feeds (wrong: git already compresses); correlation residual as the wigglegram speed metric
  (wrong: it penalised the best pair). Each time the correction came from Keith looking at the output.
- **Two late-caught hazards that could have hurt a public service or the site.** Explorer galleries linked live
  Helioviewer render URLs, so each page view would have triggered 29 server renders; and digest filenames took
  their extension from a render URL's query string, which 404'd on Pages. Both were shaped by "URL-keyed cache"
  thinking that assumed URLs end in filenames.
- **I raced the bot twice.** Pushing to main while a dispatched run was committing failed that run's push; the
  rebase fix came after the second time.

## Improvements to consider

1. **Verify from the served artifact, never from job status.** After any deploy, fetch the page and check
   last-modified or a content marker. One line in CLAUDE.md, and the habit of a cache-busted curl.
2. **On a build day, make the first hour's output a browsable view of the data, not a working pipeline.** The
   explorer was the product; the pick-1 demo was scaffolding. Next vibe day: data view first, automation second.
3. **When Keith's judgment is the signal, put my prediction in writing before he looks.** I did it once, on the
   calibration question, and being wrong was the useful result. Do it for every review round: which panel is best,
   which pair wobbles, what the anomaly tail contains.
